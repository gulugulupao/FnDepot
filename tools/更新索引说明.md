# 应用源索引维护（发版后必做）

这个源收录 5 个应用。**每次某个应用发版后，必须更新索引，否则用户端看不到更新，或装包时 sha256 校验失败。**

## 一键更新（推荐）

在某个应用仓库构建出 FPK 后，从本仓库根目录运行：

```bash
# 示例：fncleankernel 发了 v1.6.4
python3 tools/update_moo_json.py \
  --appname fncleankernel \
  --version 1.6.4 \
  --fpk /path/to/fncleankernel-V1.6.4.fpk \
  --repo gulugulupao/fncleankernel \
  --changelog "本版更新内容"
```

脚本会：从 FPK 内 manifest 读 appname/version → 算 sha256 与字节数 → 写进 `moo.json` 对应应用的 `releases`，同步顶层版本号，只保留最近 2 版。

参数说明：
- `--appname`：**必须指定**（聚合源有多个应用，不指定会更新错）
- `--version`：裸版本号，不带 v
- `--fpk`：FPK 本地路径（支持通配符）
- `--repo`：应用所在仓库（拼 Release 下载直链用）
- `--changelog`：本版更新说明

## 双平台都要更新

本源同时维护 `moo.json`（Moo）和 `fnpack.json`（FnDepot V2）。脚本默认只更新 `moo.json`。更新完 Moo 后，**同步把新的 release 节点写到 `fnpack.json` 的对应应用下**（结构相同：`releases.<版本>.packages.arm.{download_url, sha256, size}`）。

两个文件的差异：
| | moo.json | fnpack.json |
|---|---|---|
| schema_version | `"moo"` | `"2"` |
| 包级 size | 字节 | 字节 |
| 顶层 version | 跟最新版 | 无（从 releases 挑） |

## 校验

```bash
python3 -c "import json; [json.load(open(f)) for f in ('fnpack.json','moo.json')]; print('JSON OK')"
```

再确认 download_url 能匿名下载、sha256 与 GitHub Release 的 asset.digest 一致：

```bash
gh api repos/gulugulupao/<repo>/releases/tags/v<版本> --jq '.assets[] | "\(.name) \(.digest)"'
```

## 新增应用

在 `fnpack.json` 和 `moo.json` 的 `apps` 里各加一个节点，`icon_url` 指向 `icons/<repo>.png`（先把图标放进 icons/）。`apps` 的键必须等于 FPK 内 manifest 的 `appname`，大小写敏感。

## 注意

- 已发布版本不能静默换包（用户缓存校验和会失配）——要改就升版本号。
- 旧版本链接失效时，删掉 `releases` 里的旧节点即可。
- `sd15-one-gpu` 未收录：它是 x86 Docker/镜像分发，不是 fpk。
